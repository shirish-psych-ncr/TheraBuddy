# UX, navigation and clinical workflows

## Navigation

Public: /, /login, /accept-invite. Authenticated: /app/organizations and /app/:organizationId/{onboarding,dashboard,my-day,staff,children,calendar,attendance,sessions,assessments,goals,activities,equipment,reports,settings}. Child details contain overview, history, care team, goals, assessments, sessions and reports. Platform operations use a separate permission boundary under /platform-admin.

These are route families, not implemented paths. The exhaustive source inventory contains sections, modals and exceptional states as well as pages. Share layouts across disciplines; configure OT/SLT panels instead of duplicating the entire application.

## Critical journeys

1. Centre setup: identity/timezone → services → staff/roles → hours/rooms → inventory → readiness. Save partial progress; optional equipment must not block basic registry use.
2. Child onboarding: identity/caregivers → consent requirements → concerns/strengths/communication → care team → baseline/goals. Missing baseline is visible and never imputed.
3. My Day: choose appointment → verify child and precautions → mark attendance → start delivered session.
4. Session workspace: entry observations → goals → activity cards with measures and supports → exit → handoff → note review → authorized sign. Sections are navigable, not a mandatory long wizard.
5. Clinical review: compare equivalent measurements → inspect support/context/sample sizes → revise goals with new versions → approve report.
6. Change management: staff departure or equipment maintenance → affected future work → reassignment/replan → preserved historical authorship.

## Component and state map

| Component | Required behavior |
|---|---|
| Organization switcher | Visible tenant context; handles unsaved draft; clears sensitive cache |
| Child header | Stable identifier and DOB/age; avoids unnecessary sensitive detail |
| Activity recorder | Goal, activity version, measurable result, prompts/context; add/reorder/remove drafts |
| Autosave status | Saving/saved/failed/conflicted plus last confirmed save time |
| Calendar | Keyboard-accessible alternative to drag/drop; timezone and collision feedback |
| Catalogue result | Reviewed status, why matched, missing prerequisites and inventory availability |
| Note review | Data provenance, missing fields, author and explicit signature action |
| Progress chart | Baseline, units, denominator, support, protocol breaks and accessible table |
| Error/empty state | Explain what happened and a permitted next action; no fake success |

Every data view needs loading, empty, denied, not found, validation, network failure and stale/conflict designs. Clinical writes unavailable offline must say so; an in-memory unsaved form is not durable recovery. Browser close/reload can lose it. Do not silently persist identifiable data to solve that limitation.

## Visual direction

The supplied logo is a multicoloured butterfly with speech, hand and heart motifs. Preserve it as an asset; ownership/license still needs confirmation before publication. Use a calm neutral clinical workspace with restrained blue/teal accents. Do not use all logo colors as dense UI backgrounds. Tenant branding is configuration. Provide readable typography, clear selected states and non-color status labels.

Aim for WCAG 2.2 AA, semantic labels, visible focus, keyboard navigation, 200% zoom, reduced motion and generous touch targets. Verify 360px phone, tablet and desktop layouts; session forms must remain usable with a virtual keyboard. Large directories use search/filter/pagination rather than giant tables on phones. Hindi/English support is planned through message keys and locale-aware dates, with human-reviewed clinical translations; no runtime translation API dependency.
